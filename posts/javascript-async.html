JavaScript 异步编程深入理解

📅 发布于 2024-11-10 • ⏱️ 阅读时间 12 分钟
JavaScript 异步编程 前端

🎯 什么是异步编程？

在 JavaScript 中，异步编程是处理耗时操作（如网络请求、文件读写、定时器）的重要方式。与同步编程不同，异步操作不会阻塞后续代码的执行。

📚 从回调函数说起

最早的异步解决方案是回调函数：

// 回调函数示例
function fetchData(callback) {
    setTimeout(() => {
        callback('数据加载完成');
    }, 1000);
}

fetchData((data) => {
    console.log(data); // 数据加载完成
});

但回调函数存在"回调地狱"的问题： 

// 回调地狱示例
getData1((data1) => {
    getData2(data1, (data2) => {
        getData3(data2, (data3) => {
            // 嵌套太深，难以维护
            console.log(data3);
        });
    });
});

✨ Promise - 优雅的异步解决方案

Promise 是 ES6 引入的异步编程解决方案，它有三种状态：

  • Pending（进行中）
  • Fulfilled（已成功）
  • Rejected（已失败）

基本用法

// 创建 Promise
const promise = new Promise((resolve, reject) => {
    setTimeout(() => {
        const success = true;
        if (success) {
            resolve('操作成功！');
        } else {
            reject('操作失败！');
        }
    }, 1000);
});

// 使用 Promise
promise
    .then(result => {
        console.log(result); // 操作成功！
    })
    .catch(error => {
        console.error(error);
    });

Promise 链式调用

// Promise 链
fetch('/api/user')
    .then(response => response.json())
    .then(user => fetch(`/api/posts/${user.id}`))
    .then(response => response.json())
    .then(posts => {
        console.log('用户的文章：', posts);
    })
    .catch(error => {
        console.error('发生错误：', error);
    });

Promise 常用方法

// Promise.all - 等待所有 Promise 完成
Promise.all([promise1, promise2, promise3])
    .then(results => {
        console.log('所有请求完成：', results);
    });

// Promise.race - 返回最快完成的 Promise
Promise.race([promise1, promise2])
    .then(result => {
        console.log('最快的结果：', result);
    });

// Promise.allSettled - 等待所有 Promise 完成（无论成功或失败）
Promise.allSettled([promise1, promise2])
    .then(results => {
        results.forEach(result => {
            console.log(result.status); // 'fulfilled' 或 'rejected'
        });
    });

🚀 Async/Await - 终极异步方案

ES2017 引入的 async/await 让异步代码看起来像同步代码，极大提高了可读性。

基本语法

// async 函数
async function fetchUserData() {
    try {
        const response = await fetch('/api/user');
        const user = await response.json();

        const postsResponse = await fetch(`/api/posts/${user.id}`);
        const posts = await postsResponse.json();

        return { user, posts };
    } catch (error) {
        console.error('错误：', error);
        throw error;
    }
}

// 调用 async 函数
fetchUserData()
    .then(data => console.log(data))
    .catch(error => console.error(error));

并发执行

// 错误示例：串行执行（慢）
async function fetchDataSlow() {
    const user = await fetchUser();      // 等待 1 秒
    const posts = await fetchPosts();    // 等待 1 秒
    // 总共 2 秒
}

// 正确示例：并行执行（快）
async function fetchDataFast() {
    const [user, posts] = await Promise.all([
        fetchUser(),   // 同时开始
        fetchPosts()   // 同时开始
    ]);
    // 总共 1 秒
}

💡 实战技巧

1. 错误处理

async function robustFetch(url) {
    try {
        const response = await fetch(url);

        if (!response.ok) {
            throw new Error(`HTTP error! status: ${response.status}`);
        }

        return await response.json();
    } catch (error) {
        console.error('请求失败：', error.message);
        // 返回默认值或重新抛出错误
        return null;
    }
}

2. 超时控制

function fetchWithTimeout(url, timeout = 5000) {
    return Promise.race([
        fetch(url),
        new Promise((_, reject) =>
            setTimeout(() => reject(new Error('请求超时')), timeout)
        )
    ]);
}

3. 重试机制

async function fetchWithRetry(url, retries = 3) {
    for (let i = 0; i < retries; i++) {
        try {
            return await fetch(url);
        } catch (error) {
            if (i === retries - 1) throw error;
            console.log(`重试 ${i + 1}/${retries}...`);
            await new Promise(resolve => setTimeout(resolve, 1000));
        }
    }
}

⚠️ 常见陷阱

  1. 忘记 return：在 Promise 链中忘记返回值
  2. 串行执行：本可以并行的操作被串行执行
  3. 错误处理：没有正确处理 rejected 状态
  4. await 位置：在循环中不当使用 await

🎯 总结

掌握异步编程是成为优秀 JavaScript 开发者的必经之路。从回调函数到 Promise，再到 async/await，JavaScript 的异步编程越来越优雅和强大。

记住：

  • 使用 Promise 而不是回调
  • 优先使用 async/await
  • 正确处理错误
  • 注意并发和串行的选择
